Ce que ça prouve

  • Invariants tenus à toutes les échelles : verify 100 %, budget jamais dépassé (I13), 0 rupture de chaîne — de K=10 à 200 et sous 64 runs concurrents (atomes partagés cohérents).
  • Scaling propre : latence linéaire en K (pas de surcoût superlinéaire) ; débit ~20–22k agents/s constant.
  • Sharding parfait : bb_conflicts = 0, bb_writes linéaire en K, ev_dropped = 0.
Caveats honnêtes : keyless Mode A (mesure la machinerie, pas le débit LLM) ; bb_conflicts=0 car les écritures visent des pointeurs distincts (la résolution CAS est couverte par les tests unitaires) ; concurrence en vol bornée (défaut consensus = 8) → K=200 par vagues, d'où le scaling linéaire. La brique « en grande quantité » passe de non mesurée à prouvée empiriquement.

§5 Architecture

  • Couches strictes, aucun cycle : substrat → topologie → provenance → SDK → gateway.
  • Découplage par seams (WriteSink/EventSink) : provenance & dashboard se branchent sans que la topologie les connaisse.
  • Object-safety : trait Topology → exécution uniforme T1/T2/T3/Consensus.
  • Feature-gating propre : postgres/oidc/pii optionnels.
  • Concurrence sûre par construction : DashMap shardé, budget atomique, N17 task-local.
