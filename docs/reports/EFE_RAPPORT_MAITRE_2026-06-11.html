§1 Résumé exécutif

EFE productise le moat : non « un essaim d'agents de plus », mais une nuée de très petits agents (nano), déterministes, en parallèle, qui s'échangent l'information sur un substrat commun — et dont chaque pas laisse une preuve cryptographique qu'un tiers re-vérifie seul, hors-ligne.

🔒 Souverain
0 clé dans le produit ; le seul secret est le master HKDF qui signe la provenance (env, server-side).
🏠 Local
SLM sur 127.0.0.1, air-gappable, zéro egress (mode phare self-host).
✅ Vérifiable
chaque run → provenance_root re-prouvable hors-ligne (records + clé tenant).

Ce qui est livré, et ce qui manque (en une phrase)

Livré : les 3 modes, les 4 topologies parallèles, le substrat, la provenance + N17, le budget I13, les garde-fous, le dashboard, le binaire prod, Helm, et — cette session — le benchmark de scale (GO), un test Network en-process sans clé, un Dockerfile, clippy à 0 et les unwrap durcis. La nuance honnête : on ne promet jamais la reproductibilité bit-à-bit d'un LLM. On promet la re-preuve forensique (intégrité + lignée). Le Mode A déterministe, lui, est reproductible (l'ancre, ADR-007).

§3 Le substrat : comment les agents se passent l'information

Deux organes complémentaires (Keystone WS1) : un Blackboard (la vérité durable, exhaustive) et un TopicRouter (l'indice live). C'est ce qui rend « beaucoup d'agents en parallèle » viable et sûr.

Figure 2 — Le substrat (blackboard.rs, topic_router.rs, sink.rs).

Parallélisme sûr

Sharding (DashMap) : K agents écrivent des clés distinctes → shards distincts → aucun n'attend l'autre (pas de lock global). CAS (write_if(ptr, val, version)) sur la même clé : A v3→v4 OK, B « si v3 » refusé (conflit compté). Pas de perte silencieuse.

Bus = indice, BB = vérité

Le bus peut perdre (abonné lent → ev_dropped) ; l'agrégateur ne décide donc pas d'après le bus mais d'après snapshot() (exhaustif). Le live peut être imparfait sans jamais fausser le verdict. Deux seams exposent tout sans coupler la topologie.

§4 Les nano-agents & les quatre topologies

43 agents Mode A (struct Rust mono-fonction, sans poids), 6 rôles (générateurs, vérificateurs, stages, décomposeurs, mergers, juges) + le rôle Judge. Montables par nom via AgentFleet. En Mode C, le « nom » devient une instruction-prompt — la topologie ne change pas.

struct Uppercase;
impl Stage for Uppercase {
  async fn process(&self, input) -> Vec<Value> { vec![ json!({"text": text_of(input).to_uppercase()}) ] }
}    // un agent complet : pas de modèle, pas de poids, pas d'état.
Figure 3 — Les 4 patterns derrière trait Topology (object-safe). Fichiers : generate_verify.rs, consensus_topology.rs, pipeline.rs, hierarchical.rs.

Le pari S1 + l'agrégation Borda (exemple chiffré)

Sur une tâche vérifiable, la bonne réponse est souvent présente mais minoritaire ; le vote la raterait, le vérificateur/panel l'extrait. Borda : points = Σjuges ((K−1)−rang) ; gagnant = argmax ; confiance = marge / (J×(K−1)).

CandidatJuge 1Juge 2Total Borda
A1er → 21er → 24 (gagnant)
B2e → 13e → 01
C3e → 02e → 11

Escalade coût-consciente : on tente d'abord un Vote gratuit ; si confiance ≥ seuil → juges économisés (coût = K), sinon escalade. Condorcet (pairwise, fallback Copeland sur cycle) est l'alternative.

§6 Le SDK : Resolver & Meter

Le Resolver : le même nom, deux réalités

fn generator(name, id):
  g = match backend {
    Some(b) => llm_gen(b, name)        // Mode C : le NOM est une INSTRUCTION (prompt)
    None    => fleet.generator(name)?  // Mode A : le NOM est une CLÉ de flotte
  }
  meter_gen(g, meter, id)              // ENVELOPPE : budget + provenance + N17 + observateur

La topologie ne change pas d'une ligne entre Mode A et Mode C. Le vérificateur de T1 reste toujours déterministe (flotte), même en self-host — l'ancre a-posteriori (ADR-002).

Le Meter : chaque pas gouverné et prouvé

Autour de chaque appel : (a) charge (BudgetGuard, I13) ; (b) scope N17 (task-local) ; (c) capture (AgentCallRecord → ProvenanceRecorder) ; (d) observe (dashboard). Agents et topologies n'en savent rien.

§7 Le moat : provenance vérifiable

Chaque pas → un AgentCallRecord (hash entrée/sortie blake3, rôle, parents DAG, lien N17, wall_at exclu du hash → root reproductible). Chaîne HMAC signée par la clé tenant (HKDF), jamais transmise.

Figure 5 — La chaîne HMAC + DAG et sa re-preuve (ADR-009 : « le endpoint verify EST le produit »).

verify_swarm (4 contrôles) : (0) ordre canonique déterministe ; (1) chain_intact (HMAC : insertion/suppression/réordonnancement) ; (2) content_intact (blake3 : mutation d'un octet) ; (3) dag_consistent (parents existants + lectures non-fantômes par version). + traced_pct. Une falsification : content casse → réparer change le hash → chain casse → réparer la chaîne exige la clé tenant (absente). Détectée ET localisée.

§8 Pont N17 — forensique par-appel

Pour chaque agent Mode C, un LlmProvenanceRecord capte modèle, seed, paramètres, hash prompt/réponse, latence, re-tentatives. L'AgentCallRecord le référence via llm_provenance_id.

Figure 6 — Le seam task-local : concurrence-safe (un puits par appel d'agent). Une re-tentative n'émet qu'UN record final (avec retry_count). Prouvé réel : Claude 4/4 cohérents, gemma3:12b.

§9 Mode Network (Inc.4.b)

Le SDK refuse Network in-process (pas de clés). La passerelle l'interpose un routeur : resolve_mode traduit Network{provider} → SelfHost{routeur/v1, modèle}, allow_remote=true, + tarif Network préservé. La passerelle parle OpenAI-compat sans auth ; le routeur injecte la clé.

Figure 7 — La passerelle reste keyless ; le routeur (LiteLLM / efe-llm-router) détient les clés. Prouvé réel (Claude 3.5 Sonnet) et en-process sans clé (test d'intégration CI).

Cost-governance (corrigé) : la traduction faisait tomber le tarif à 0¢ ; resolve_mode renvoie désormais le tarif à préserver, injecté au budget (respecte un tarif client). spent_cents > 0 prouvé.

§10 Backends locaux & résilience

En Mode C, les agents appellent un LLM via LocalBackend : keyless, local par défaut, shell-out curl vers 127.0.0.1, sans en-tête d'auth, sans dépendance réseau crate.

  • Garde-fou G2 : build_local_backend refuse un endpoint non-local par défaut (RemoteBackendDenied) ; seul Network (egress assumé) passe allow_remote=true.

§12 PII & dashboard

PII opt-in (G9)

Détection LOCALE (regex : email/SSN/CB/IBAN/IP/tél), sans réseau → compatible egress=deny. Caviarde la présentation (sortie + previews + repos), pas les records → verify re-prouve l'original. Opt-in par tenant (Off/Detect/Redact/Strict).

Dashboard live (4 panneaux)

UI vanilla (un HTML, zéro build JS), SSE. Trafic inter-agent · consensus (matrice ballots) · provenance (root + VERIFIED) · budget. Le « on voit l'essaim travailler ». Lossy par conception (live ≠ audit).

UX : à la fin d'un run, le serveur ferme le flux SSE → le badge passe « terminé » puis « interrompu » (onerror sur fermeture propre). Pas un échec (provenance VERIFIED). Correctif 1 ligne identifié.

§17 Ce qui manque (analyse de gaps, honnête)

Cadrage : la vision a trois mots — nano (✅), en grande quantité (🟡), se passent l'info en parallèle (🟡, le vrai trou). Bonne nouvelle : les primitives existent (CAS versionné, subscribe, ReliableTopic) ; les manques sont surtout des topologies/politiques non construites + de la persistance/exposition — pas des réécritures.

#Manque (vérifié dans le code)CentralitéEffort
AInfluence mutuelle : aujourd'hui fan-out + agrégation ; aucun agent ne lit/réagit au travail d'un pair en cours (gossip ADR-003 / debate ADR-005 = gated, non construits). Une topologie T-Gossip/T-Debate itérative manque (le substrat la permet déjà).🔴 cœurmoyen
BTaille d'essaim adaptative (K fixe ; concurrence en vol plafonnée 8/16, non dimensionnée CPU ; escalade binaire seulement).🟠 hautemoyen
CMessagerie ciblée agent↔agent (le bus est broadcast par topic ; pas d'adressage point-à-point).🟠 hautemoyen
DPersistance N17 : StoredRun ne stocke pas llm_records → le « pourquoi » par-appel est éphémère ; verify_bridge non rejouable hors-ligne.🟡 moy.faible
EEndpoint /replay : replay.rs (rejeu déterministe, ADR-007) existe mais n'est pas exposé (seul le rejeu du bus SSE l'est).🟡 moy.faible
GAdmission-control des runs concurrents (la passerelle spawn sans limite globale) + deadline/annulation au niveau run.🟡 moy.faible
FMémoire/apprentissage inter-runs (agents sans état ; curation/active-learning non câblés).🟢 basseélevé
HSubstrat distribué (tout in-process : DashMap) — plafond ultime de « grande quantité ».🟢 basseélevé
Recommandation (trancher) : construire A — T-Gossip : round 0, K agents écrivent /draft/i ; rounds 1..R, chaque agent relit les drafts des pairs (subscribe_prefix + snapshot) et révise (CAS) ; arrêt par quiescence/convergence ; agrégation Borda. Ça réutilise tout l'existant (substrat, provenance, budget, N17) et exerce enfin le DAG causal_parents. Les quick wins D + E + G sont à faible effort si on veut d'abord durcir l'audit/ops.
