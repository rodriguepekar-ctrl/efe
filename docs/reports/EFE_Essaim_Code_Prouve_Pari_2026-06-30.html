Note de cadrage · au niveau agents · ce qui est codé ≠ prouvé ≠ pari

L'essaim, au juste

« Ce que l'on a codé, est-ce de petits agents qui se passent de l'information à des agents LLM entre eux ? » — la réponse exacte, vérifiée dans le code, pour ne rien sur-revendiquer à l'oral.
Oui — sur le substrat. Ce qui est construit EST un essaim de petits LLM qui se passent des artefacts typés en parallèle, via un blackboard partagé et des topologies (pipeline, consensus, gossip, débat), le tout scellé et re-prouvable. Sur ce point, le modèle mental et le code coïncident. Mais trois précisions séparent ce qui est codé de ce qui est prouvé et de ce qui reste un pari — et les confondre casserait la seule chose qui rend le pitch crédible, l'honnêteté. Un : « à très peu de paramètres » veut dire petits modèles de langage, pas micro-réseaux sur-mesure. Deux : le passage d'information a deux formes au statut de preuve opposé — l'agrégation (voter, médiane) est codée et mesurée et réfutée ; la communication (artefacts vérifiés dans la boucle) est codée mais reste un pari ouvert, non prouvé. Trois : la valeur prouvée et vendable n'est pas « les agents qui se parlent » — c'est la couche autour d'eux : provenance, mesure, routeur, souveraineté. Cette note fixe la carte, pour que tu dises exactement ce qui est vrai : « on a codé l'essaim et l'appareil qui mesure honnêtement s'il aide ».

§1 La question, et la réponse en une ligne

La question. « Ce que l'on a codé, est-ce de petits agents qui permettent de passer des informations à des agents LLM entre eux, en parallèle ? » — autrement dit, le code correspond-il à la thèse de départ (l'essaim de petits modèles communicants) ?

La réponse en une ligne. Oui, le substrat est exactement cela — un essaim de petits LLM qui se passent des artefacts typés en parallèle, scellé et re-prouvable, est codé, tourne et est testé. Mais la valeur prouvée n'est pas ce passage d'information en soi : sous sa forme « agrégation » il est réfuté, sous sa forme « communication vérifiée » il est un pari ouvert ; ce qui est prouvé et vendable, c'est l'appareil de confiance et de mesure qui entoure l'essaim.

Le reste de cette note détaille les trois précisions qui font la différence entre « on pense la même chose » (vrai sur le substrat) et « on revendique la même chose » (à manier avec rigueur). Chacune est vérifiée dans le code, pas supposée.

§2 Ce qui est CODÉ : l'essaim de petits LLM qui se passent l'info

Sur le substrat, le code est la thèse. Vérifié dans les sources :

  • Les agents = des rôles tenus par de petits LLM. ClientMode distingue Mode A (keyless / scripté / déterministe — pour le seam de test) et Mode C (LLM réel via Ollama / vLLM — un SLM type phi4-mini, llama3.2-1b). Un agent est un rôle + un contrat d'entrée/sortie typé, adossé à un appel de petit modèle.
  • Ils se passent l'information — deux mécanismes réels. Un blackboard partagé (efe-blackboard : un store indexé par JSON-pointer, versionné par champ, chaque écriture attribuée à un AgentId, primitive d'écriture conditionnelle write_if) ; et des topologies (efe-swarm-topology : Generate-Verify, Pipeline, Hiérarchique, Consensus, gossip, débat) qui définissent comment l'info circule.
  • En parallèle. Les topologies de flotte lancent K agents à la fois (TopologySpec::consensus(..., 5)), avec un dimensionnement par vagues.
  • Scellé et re-prouvable. swarm.run(task, topology, budget) renvoie un provenance_root qu'un tiers re-vérifie (verify_swarm), budget plafonné jamais dépassé. Chaque appel de modèle et chaque message est capté pour la provenance (N17).
L'essaim tel qu'il est codé : K petits LLM en parallèle, un blackboard partagé versionné où ils déposent des artefacts typés, des topologies qui orchestrent le flux, et un sceau de provenance re-prouvable. Sur ce substrat, le modèle mental et le code coïncident.

Précision de statut : le bout-en-bout avec de vrais petits LLM (Mode C) est prouvé dans un exemple sur Ollama local ; les quatre topologies tournent réellement. Le câblage de Mode C dans le SDK unifié est la tranche d'ingénierie suivante — l'idée, elle, est démontrée.

§3 Précision 1 : « très peu de paramètres » = petits LLM

Dans le code, un agent n'est pas un réseau neuronal sur-mesure à quelques milliers de paramètres. C'est un petit modèle de langage (SLM) qui tient un rôle — résolu par nom depuis une flotte, et exécuté en Mode C contre un endpoint vLLM/Ollama.

Pourquoi la formulation compte. « Petits LLM spécialisés » est exactement la thèse SLM-swarm de Kovant — donc cela s'aligne parfaitement. Mais dire « agents à très peu de paramètres » laisse imaginer des micro-réseaux bespoke, ce qui n'est pas ce qui est codé. Pour rester juste à l'oral : « de petits modèles de langage, spécialisés par sous-tâche ».

§4 Précision 2 : le passage d'info a deux formes, au statut de preuve opposé

C'est la précision la plus importante, et elle est visible dans le code lui-même. La sortie d'une topologie (TopologyOutput) porte un champ decided_pattern (vote / borda / condorcet) et un drapeau escalated : le code implémente le passage-comme-agrégation et l'appareil qui le mesure. Or les deux formes ne valent pas pareil :

La correction de modèle mental à intégrer. Le passage d'information existe dans le code — ce n'est pas en question. Ce qui est en question, c'est s'il améliore le résultat. La réponse mesurée est : non pour l'agrégation (réfutée, re-prouvablement), peut-être pour la communication vérifiée (pari, derrière une porte de falsification, avec un garde anti-poison — un juge-oracle de correction). Tenir cette distinction est ce qui te distingue d'un vendeur d'émergence.

§5 Précision 3 : la valeur prouvée = la couche autour, pas le passage d'info

Si l'essaim-qui-communique est le substrat, ce qui est prouvé, prêt et vendable est la couche qui l'entoure — celle qui rend n'importe quel essaim d'agents digne de confiance et mesurable :

  • Provenance — re-prouver ce que chaque agent et chaque message a fait (chaînes scellées, vérifieur zéro-dépendance qu'un tiers re-compile).
  • Mesure — trancher, sans tricher, où un petit substitue un gros, et à quel coût (non-infériorité, contrôle d'erreur de famille, harnais de falsification).
  • Routeur — garder le petit quand un diagnostic le permet, escalader vers le gros sinon ; et sceller chaque décision de routage.
  • Souveraineté — egress refusé, clé qui ne sort jamais, déploiement local.

Le renversement à garder en tête. Tu ne vends pas « nos agents qui se parlent = intelligence ». Tu vends « on rend n'importe quel essaim d'agents auditable, mesuré et souverain » — et l'essaim communicant est le terrain sur lequel cette couche démontre sa valeur. C'est cette couche, pas le passage d'info, qui constitue le moat prêt aujourd'hui.

§6 Le piège à l'oral — et la formulation juste

❌ À NE PAS dire. « On a fait de petits agents qui se passent l'info entre LLM, c'est ça la valeur. » → tu revendiques le truc réfuté (agrégation) ou non prouvé (communication), et tu casses ta propre marque d'honnêteté — la seule chose qui te distingue dans un marché saturé de promesses.

✅ À dire. « On a codé l'essaim de petits agents qui se passent des artefacts typés en parallèle — ET l'appareil qui mesure honnêtement si ce passage aide. Le premier, c'est l'idée ; le second, c'est ce qui en fait un produit. Et la mesure tranche : le vote n'aide pas (réfuté), la communication-avec-vérification peut-être (pari ouvert, mesuré derrière une porte), et pendant ce temps la provenance et le routeur se vendent quoi qu'il arrive. »

Cette carte est vérifiée dans les sources EFE le 2026-06-30 — efe-swarm-sdk (Mode A/C, TopologySpec, swarm.run/verify_swarm), efe-blackboard (store versionné, écriture attribuée), efe-swarm-topology (TopologyOutput, decided_pattern, AgentContribution), et l'appareil de mesure efe-bench-inference (réfutation de l'agrégation). « Codé » signifie présent et testé ; « prouvé valable » signifie mesuré comme apportant un gain ; « pari » signifie une hypothèse à falsifier, jamais une revendication.
