# D17-1 — `D17BackupStaleFull` / `D17BackupStaleDiff`

## Symptom

* `D17BackupStaleFull` fires when no successful **full** Postgres
  backup has completed in the last **24 h**.
* `D17BackupStaleDiff` fires when no successful **diff** backup
  has completed in the last **1 h**.

## Impact

RPO target (5 min) is being silently extended. If a Postgres
primary fails right now, recovery will reconstruct the database
from the last full + WAL replay — but if WAL archiving is also
broken (often the same root cause), data loss can reach **several
hours**.

## Triage (5 min)

```bash
# 1. List recent backup CronJob runs and their statuses.
kubectl --namespace efe get jobs -l app.kubernetes.io/component=backup \
    --sort-by=.metadata.creationTimestamp | tail -5

# 2. Inspect the most-recently failed Job's logs.
kubectl --namespace efe logs job/efe-backup-postgres-full-<timestamp> --tail=200

# 3. Check the PG primary is healthy + reachable.
kubectl --namespace efe exec deploy/efe-server -- \
    pg_isready -h $EFE_PG_HOST -p $EFE_PG_PORT

# 4. Check the backup S3 bucket is reachable.
kubectl --namespace efe exec deploy/efe-server -- \
    aws s3 ls s3://efe-backups-prod/ --max-items 5
```

## Common causes (sorted by likelihood)

| # | Cause | Detection | Fix |
|--:|-------|-----------|-----|
| 1 | pgBackRest cipher passphrase Secret out of sync with prod | Pod logs : "AES decryption failed" | Re-sync `efe-backup-config` Secret via SealedSecrets / external-secrets controller |
| 2 | S3 bucket policy modified, denying writes from the cluster IAM role | Pod logs : "AccessDenied" | Restore bucket policy ; verify IAM role assumption works |
| 3 | NetworkPolicy egress blocking S3 (port 443) | Pod logs : "connection timeout" | Verify `templates/networkpolicy-backup-egress.yaml` is applied |
| 4 | PG primary OOM / disk full | `kubectl top pod` + `df -h` on the PG node | Scale up resources OR delete old WAL files |
| 5 | pgBackRest version regression | `kubectl exec ... pgbackrest version` | Pin pgBackRest version in the Helm chart |

## Mitigation

```bash
# Once root cause identified + fixed, manually trigger a backup
# to clear the stale alert :
kubectl --namespace efe exec deploy/efe-server -- \
    efe-backup snapshot --source=postgres --kind=full \
        --label="manual-recovery-$(date -u +%Y%m%dT%H%M%SZ)"
```

The `D17BackupStaleFull` alert clears within 1 minute of a
successful run setting `efe_backup_last_success_timestamp`.

## Escalation

* **If unresolved after 1 h** → page DBA on-call.
* **If unresolved after 4 h** → escalate to platform-engineering
  lead. Consider notifying customer success of potential RPO
  exposure for Tier 1 contracts.
