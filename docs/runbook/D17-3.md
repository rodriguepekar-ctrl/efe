# D17-3 — `D17BackupRpoViolation`

## Symptom

`efe_backup_rpo_seconds > 300` (5 min target) sustained for 5 min.
The age of the most recent WAL archive has exceeded the contractual
RPO.

## Impact

🔴 **CRITICAL** : if a Postgres primary fails right now, the
recovery point will be more than 5 min in the past — violating
the Tier 1 customer DPA.

## Triage (5 min)

```bash
# 1. Confirm WAL archiving is actually running.
kubectl --namespace efe exec deploy/efe-server -- \
    psql -c "SELECT name, setting FROM pg_settings \
             WHERE name IN ('archive_mode', 'archive_command');"
# Expected : archive_mode=on, archive_command starts with 'pgbackrest archive-push'.

# 2. Check the WAL archive status.
kubectl --namespace efe exec deploy/efe-server -- \
    psql -c "SELECT * FROM pg_stat_archiver;"
# Look for archived_count vs failed_count + last_archived_time.

# 3. Inspect the pgBackRest archive-push log.
kubectl --namespace efe exec deploy/efe-server -- \
    tail -100 /var/log/postgresql/pgbackrest.log | grep archive-push
```

## Common causes

| # | Cause | Detection | Fix |
|--:|-------|-----------|-----|
| 1 | pgBackRest archive-push hung on S3 timeout | `pg_stat_archiver` shows `failed_count` rising | Restart Postgres ; investigate S3 latency |
| 2 | `archive_async=y` queue full | Queue dir > 4 GiB (default `archive-push-queue-max`) | Drain : `pgbackrest --stanza=main archive-push-async` ; bump queue-max in config |
| 3 | Disk full on the PG primary | `df -h` on the PG node shows 100% | Free WAL space OR scale storage |
| 4 | Replication lag pinning WAL files | `pg_replication_slots` shows lag | Drop / catch up the lagging replica |

## Mitigation

If the WAL queue is recoverable :

```bash
# Drain the async archive queue.
kubectl --namespace efe exec deploy/efe-server -- \
    pgbackrest --stanza=main archive-push-async
```

If the queue cannot be drained quickly enough, **escalate immediately**
— customer DPA exposure increases per-second.

## Escalation

* **Always page DBA on-call immediately on this alert.** RPO
  violation is contractual.
* **If unresolved after 30 min** → also notify customer success
  for proactive Tier 1 communication.
* **If RPO exceeds 1 h** → consider triggering an out-of-cycle
  full backup as a safety net.
