# D17-5 — `D17DrRtoViolation`

## Symptom

`histogram_quantile(0.95, efe_dr_drill_duration_seconds_bucket)` >
1800 s (30 min target) sustained for 30 min. The p95 drill
duration over the last day exceeds the RTO target.

## Impact

* **Contractual** : the Tier 1 DPA documents an RTO of 30 min. A
  p95 above the target means we cannot defensibly claim the SLA
  is met for a real incident.
* **Compounding** : if the drill itself takes > 30 min, the
  CronJob's `activeDeadlineSeconds` (45 min) may start aborting
  drills mid-flight, creating a `D17DrDrillStale` cascade.

## Triage (5 min)

```bash
# 1. Identify which drill stage is the bottleneck. Each stage
#    of dr/restore.sh logs its duration ; pull the most recent
#    completed drill's log.
kubectl --namespace efe logs job/efe-dr-drill-<latest> | \
    grep -E 'Step [0-6]/6'

# 2. Compare against historical timing in dr/timing.json (per drill).
ls -lt /var/log/efe-dr-drill/timing-*.json | head -5

# 3. Profile pgBackRest restore specifically (usually the bottleneck).
kubectl --namespace efe logs job/efe-dr-drill-<latest> | \
    grep -E 'pgbackrest .* restore' | head -20
```

## Common causes (sorted by likelihood)

| # | Cause | Typical impact | Fix |
|--:|-------|---------------|-----|
| 1 | Postgres backup size grew without proportional `process-max` bump | Restore goes from 10 min to 25 min | Bump `process-max` in pgBackRest config from 4 → 8 |
| 2 | S3 cross-region restore (drill ns in a different region than prod) | +5-10 min S3 download latency | Enable cross-region replication on the backup bucket OR pin drill region to match prod |
| 3 | WAL replay backlog (drift between full + restore time) | +10-20 min WAL apply | Bump full backup frequency OR reduce diff retention |
| 4 | Verifier suite (5 verifiers) running serially | ~2 min added | Run verifiers in parallel (DT-D17.X candidate) |

## Mitigation

```bash
# If the bottleneck is pgBackRest restore, bump process-max
# (impact : faster restore, more concurrent S3 connections).

# Edit deploy/helm/efe/values.yaml :
backup:
  postgres:
    processMax: 8       # was 4

# Then helm upgrade to apply.
helm upgrade efe ./deploy/helm/efe -f values-prod.yaml --namespace efe
```

If the drill is consistently over-budget by < 5 min, this is a
"soft" RTO violation — schedule a remediation sprint but don't
escalate immediately. If over-budget by > 10 min, the SLA is
genuinely at risk.

## Escalation

* **If p95 > 35 min sustained** → page platform-engineering
  immediately. SLA exposure.
* **If p95 > 60 min** → consider declaring a customer-facing
  incident if any Tier 1 contract has explicit RTO clauses.
