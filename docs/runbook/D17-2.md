# D17-2 — `D17BackupFailureRate`

## Symptom

`rate(efe_backup_runs_total{result="failed"}) / rate(efe_backup_runs_total) > 0.1`
sustained for 10 min. More than 10 % of backup attempts are
failing.

## Impact

The backup pipeline is degraded but not yet stale. Each
successive failure consumes the retry budget ; if the rate stays
elevated, the scheduled CronJob will eventually skip cycles → SLO
violation → user-visible RPO degradation.

## Triage (5 min)

```bash
# 1. Identify which {source, type} is failing.
# Open Grafana panel "D17 backup failure rate by source/type" or :
kubectl --namespace efe exec deploy/efe-server -- \
    curl -s http://localhost:9090/metrics | grep efe_backup_runs_total

# 2. Tail a recent failed Job's logs (replace <timestamp>).
kubectl --namespace efe get jobs -l app.kubernetes.io/component=backup \
    -o json | jq '.items[] | select(.status.failed > 0) | .metadata.name'

# 3. Inspect the audit-chain emission for the failure event.
kubectl --namespace efe exec deploy/efe-server -- \
    psql -c "SELECT timestamp, event, payload->>'error_kind', \
                    payload->>'error_message' \
             FROM audit_log \
             WHERE event = 'backup.snapshot' \
               AND payload->>'status' = 'failed' \
             ORDER BY timestamp DESC LIMIT 5;"
```

## Common causes

| # | Cause | Symptom | Fix |
|--:|-------|---------|-----|
| 1 | Transient S3 5xx | Random failures, sometimes pass on retry | Wait 15 min ; check AWS health page |
| 2 | Postgres replication lag exhausting WAL slot | pgBackRest "WAL segment missing" | Increase `wal_keep_size` ; investigate replication slot |
| 3 | `EFE_BACKUP_VAULT_TOKEN_PATH` Secret rotated without ConfigMap update | Vault snapshot fails with 403 | Re-mint Vault token ; update SealedSecret |
| 4 | Helm chart upgrade bumped retention without proportional storage | "no space left on device" | Bump PVC size OR reduce retention |

## Mitigation

```bash
# If the root cause is transient, you can manually retry the
# failing source :
kubectl --namespace efe exec deploy/efe-server -- \
    efe-backup snapshot --source=<source> --kind=<kind> \
        --label="retry-$(date -u +%Y%m%dT%H%M%SZ)"
```

If the failures are concentrated on a single source (e.g. all
`bundles` fails but `postgres` + `vault` succeed), scope the
investigation to that source's external dependency.

## Escalation

* **If failure rate > 50 %** → immediate escalation. Backup
  pipeline is effectively offline.
* **If unresolved after 2 h** → page DBA on-call.
