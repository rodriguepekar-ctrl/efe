# D17-4 — `D17DrDrillStale`

## Symptom

`time() - efe_dr_drill_last_success_timestamp > 14d` sustained for
30 min. The weekly DR drill has not succeeded in over 2 weeks.

## Impact

* **Compliance** : the SOC 2 + RGPD posture documents commit to
  weekly drills. A stale drill is an audit finding for any
  Tier 1 customer due-diligence.
* **Risk** : the actual restore path may have regressed since the
  last successful drill ; we don't know if the documented RTO
  (30 min) still holds.

## Triage (5 min)

```bash
# 1. List recent drill Job runs and their statuses.
kubectl --namespace efe get jobs -l app.kubernetes.io/component=dr-drill \
    --sort-by=.metadata.creationTimestamp | tail -5

# 2. Inspect the most-recent drill Job's logs.
kubectl --namespace efe logs job/efe-dr-drill-<latest> --tail=300

# 3. Check the verifier suite outcome (which step failed).
kubectl --namespace efe logs job/efe-dr-drill-<latest> | \
    grep -E '✓|✗' | head -20
```

## Common causes

| # | Cause | Symptom | Fix |
|--:|-------|---------|-----|
| 1 | `AuditChainVerifier` failing : HMAC chain broken | Verifier output : "row N hmac mismatch" | Investigate audit chain integrity ; if intact in prod, the drill restore is corrupting it (Vault snapshot age ≠ DB age) |
| 2 | `BundleSignatureVerifier` failing : bundle Ed25519 invalid | Verifier output : "bundle .* signature mismatch" | Verify trust store + bundle bucket alignment |
| 3 | `OidcReachabilityVerifier` failing : JWKS endpoint unreachable from drill ns | Curl to JWKS endpoint times out | Check NetworkPolicy egress for the drill namespace ; check IdP availability |
| 4 | `ExecuteSmokeVerifier` failing : Execute RPC returned error | grpcurl exit non-zero | Check that catalog smoke + bundles loaded correctly first ; the Execute failure is usually a downstream effect |
| 5 | Drill CronJob suspended (e.g. by an operator who forgot to re-enable) | `kubectl get cronjob/<dr-drill> -o yaml \| grep suspend` shows true | Re-enable : `kubectl patch cronjob ... -p '{"spec":{"suspend":false}}'` |

## Mitigation

Trigger a manual drill to confirm the runbook works :

```bash
# Spin a kind cluster with the test harness.
./dr/setup-test-env.sh --cluster-name efe-dr-manual

# Run a full restore + smoke against it.
./dr/restore.sh <latest-backup-id> --target drill

# Inspect timing.json for RTO.
jq '.duration_seconds, .rto_target_seconds' dr/timing.json
```

If the manual drill **succeeds**, the issue is the CronJob
configuration (likely cause #5 above). If the manual drill
**fails**, it's a real regression — escalate to platform-engineering.

## Escalation

* **Always escalate within 24 h** of this alert firing.
* **If unresolved after 7 d** → block the next prod deployment
  until the drill works again. SOC 2 audit finding territory.
