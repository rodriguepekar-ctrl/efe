# D17-7 — `D17BackupS3Unreachable`

## Symptom

`up{job="efe-backup-s3-probe"} == 0` for 5 min. The blackbox probe
to the backup S3 bucket has been failing.

## Impact

🔴 **CRITICAL** : new backups cannot be written. Existing backups
cannot be read for restore. The backup pipeline is **effectively
offline** until S3 reachability is restored.

If this alert fires AND the cluster fails simultaneously, recovery
is **blocked until S3 comes back**.

## Triage (5 min)

```bash
# 1. Check the AWS S3 service health page :
#    https://health.aws.amazon.com/health/status
# (Look for the region of your backup bucket.)

# 2. Test S3 reachability directly from a backup pod.
kubectl --namespace efe exec deploy/efe-server -- \
    aws s3 ls s3://efe-backups-prod/ --max-items 1
# Expected : list of objects.
# Common errors :
#   - "could not connect to the endpoint URL" → DNS / network
#   - "AccessDenied" → IAM role rotation / policy change
#   - "InvalidAccessKeyId" → credentials expired

# 3. Verify the IAM role assumption is working.
kubectl --namespace efe exec deploy/efe-server -- \
    aws sts get-caller-identity
```

## Common causes

| # | Cause | Detection | Fix |
|--:|-------|-----------|-----|
| 1 | AWS regional outage | AWS health page shows red | Wait it out ; backups will resume automatically when S3 returns |
| 2 | NetworkPolicy egress blocked (e.g. Helm chart misapplied) | aws cli error : "couldn't connect" | Re-apply `templates/networkpolicy-backup-egress.yaml` |
| 3 | IAM role rotation broke the assumption | `aws sts get-caller-identity` returns 403 | Re-bind ServiceAccount annotation : `eks.amazonaws.com/role-arn=...` |
| 4 | Cluster DNS broken | nslookup of S3 endpoint fails | Restart `coredns` pods |
| 5 | Bucket policy modified, denying our IAM principal | `aws s3 ls` returns AccessDenied | Restore bucket policy from terraform / git |

## Mitigation

If the cause is a regional outage (cause #1) :

```bash
# Document the outage start time + estimated AWS recovery in the
# incident ticket. No mitigation possible until S3 returns.

# OPTIONAL : if the prod cluster is healthy, take a local snapshot
# to a NFS / EBS volume as a stop-gap (must be migrated to S3 once
# AWS recovers).
kubectl --namespace efe exec deploy/efe-server -- \
    pgbackrest --stanza=main --type=full --output=path \
        backup --repo=2  # if a secondary local repo is configured
```

If the cause is configurational (cause #2-5), apply the targeted
fix and the alert will clear within 1 minute of the next probe
succeeding.

## Escalation

* **Always page on-call platform-engineering immediately on this
  alert.** S3 unreachable = backup outage.
* **If outage > 1 h AND it's our config (not AWS)** → bring in
  whoever wrote the SealedSecret or IAM role binding.
* **If AWS regional outage > 4 h** → consider failing over to the
  backup bucket's cross-region replica (if `backup.bundles.crossRegion=true`
  is set in Helm values).
