## Scope

(`scripts/backfill-tolerance-used.sh`) against real historical NDJSON

## Defects found

| Code         | Class         | Decision    | One-line description |
|--------------|---------------|-------------|----------------------|
| D-S3-P4-1    | Doc/code drift | fix-in-S3   | The `lookup_tolerance` function returns hardcoded git SHA placeholders (`abc1234`, `def5678`) in the `override_reason` field of backfilled rows.  These are deliberately fake (the production v2 will use real `git log` lookups).  Add a clear comment to both the script body AND the golden file header that these are placeholders. |
| D-S3-P4-2    | Process gap   | G-XX (G-PR27-S5-GOLDEN-REGEN) | No documented procedure for regenerating the golden file when fixtures legitimately change (e.g., when a new pre_g11_ndjson case is added).  The Day 4 test `dry_run_byte_identical_to_golden_file` provides a diff hint but doesn't document the regeneration command in a stable location.  Action : add a section to `docs/process/` documenting the regeneration command. |
| D-S3-P4-3    | Spec violation | G-XX (G-PR27.1-COSIGN-INSTALL) | The `--sign` mode requires cosign on PATH, but the CI workflow `pr27-tolerance-used.yml` does NOT install cosign.  Currently the `--sign` mode is not exercised by CI.  Production rollout S5-S8 will need `sigstore/cosign-installer@v3` added to the workflow.  Deferred to PR #27.1 alongside the audit-reader crate. |

**Triage rationale** :
- D-S3-P4-1 is a docs/comment improvement, no production code change.

- D-S3-P4-2 is a process gap that warrants a separate process doc

## Fix-in-S3 patch applied

Updated the golden file header (`bench/fixtures/backfill_golden_diff.txt`)
to make the placeholder hashes visible :

```
The override_reason strings reference fake git SHA hashes (`abc1234`,
`def5678`) as PLACEHOLDERS.  These are intentionally fake — the
production v2 of the backfill tool (deferred to PR #27.1) replaces
the hardcoded lookup table with real `git log --before <applied_at>`
+ `git show <commit>:bench/scenarios/<scenario>.yaml` invocations,
producing real SHA hashes.  Until then, these placeholders document
the contract surface.
```

Also added the same note to the script's header docstring.
