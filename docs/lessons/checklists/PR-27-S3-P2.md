## Scope

This pass traces the code paths of the verdict aggregator at the
mini-aggregator level (`pretend_aggregator_emit_rows`) and the
underlying `compute_verdict` + `resolve_effective_tolerance` functions.
Pure-function discipline, branch coverage, determinism, and the
absence of dead code paths are verified.

---

## Checklist items

- [x] **Item 1** — `resolve_effective_tolerance` is pure (no I/O, no
  mutability, no `Utc::now()` internal call).
  - **Result** : PASS — Manual trace of the function body confirms no
    I/O or clock access.  `applied_at` is parameter-injected.
  - **Verified by** : `grep "Utc::now\|std::fs\|std::env" effective_tolerance.rs`
    returns matches only in `EnvContext::from_process_env` (not in resolver).

- [x] **Item 2** — The 4 source branches of the resolver are mutually
  exclusive and exhaustive : `RuntimeOverride > GpuRunnerOverride > Yaml >
  NoToleranceDefined` (precedence order).
  - **Result** : PASS — Each branch has a `return` statement.  No
    fallthrough possible.  4 unit tests cover the 4 branches independently.

- [x] **Item 3** — Precedence env-var > gpu_override is correctly
  implemented and tested.
  - **Result** : PASS — Test `resolve_env_override_takes_precedence_over_gpu_override`
    exercises the case where both env-var AND gpu_override are active ;
    env-var wins.

- [x] **Item 4** — `pretend_aggregator_emit_rows` calls
  `resolve_effective_tolerance` exactly once per metric (no redundant calls).
  - **Result** : PASS — Manual trace of the for-loop confirms one call
    per `emit_metrics` entry.

- [x] **Item 5** — The `applied_at` parameter is propagated unchanged
  to `tolerance_used.applied_at` and to the row-level `applied_at`.
  - **Result** : PASS — No transformation, no truncation.  Test
    `aggregator_emits_applied_at_subfield` pins byte-equality.

- [x] **Item 6** — `compute_verdict` matrix 4 directions × 4 verdicts +
  2 sentinels is exhaustive.  The 18 logical cells are covered.
  - **Result** : PASS — Test `matrix_completeness_walks_all_cells`
    explicitly walks all (direction, observed) combinations.  No panic
    on any combination.

- [x] **Item 7** — `compute_verdict_audit_explanation` returns the same
  verdict string as `compute_verdict` for the same inputs (round-trip
  property).
  - **Result** : PASS — Test `audit_explanation_matches_verdict_string`
    covers 4 directions × multiple observed values + 2 sentinels.

- [x] **Item 8** — Defensive `INCONCLUSIVE` fallback for ill-formed
  combinations (e.g. `direction=NoMoreThan + value=Range`) is correctly
  implemented.
  - **Result** : PASS (but see D-S3-P2-1) — Test
    `defensive_inconclusive_for_ill_formed_combinations` covers
    NoMoreThan+Range and WithinRange+Scalar.  Missing : Exactly+Range
    explicit coverage.

- [x] **Item 9** — No dead code paths in `effective_tolerance.rs`.
  - **Result** : PASS — `cargo clippy --warn dead_code` does not flag
    any item in the module.

- [x] **Item 10** — All `pub fn` returning `Self` or rich types have
  `#[must_use]` (Day 1 audit AD-AUDIT compliance).
  - **Result** : PASS — Day 1 audit pass 5 already confirmed this ;
    re-verified by `grep "pub fn .* -> .*Self\|pub fn .* -> .*Effective\|pub fn .* -> .*Tolerance"`
    cross-referenced with `grep "#\[must_use\]"`.

## Fix-in-S3 patch applied

Added in `bench/harness/src/compare/effective_tolerance.rs::tests::defensive_inconclusive_for_ill_formed_combinations` :

```rust
// Ill-formed : direction=Exactly but value=Range (added by S3 P2 audit)
let ill_formed_3 = EffectiveTolerance {
    value: Some(ToleranceValue::Range([95.0, 99.5])),
    unit: ToleranceUnit::Pct,
    direction: ToleranceDirection::Exactly,
    source: ToleranceSource::Yaml,
    applied_at: Some(now()),
    override_reason: None,
};
assert!(ill_formed_3.validate_internal_consistency().is_err());
assert_eq!(compute_verdict(Some(97.0), &ill_formed_3), "INCONCLUSIVE");
```

Test re-run post-fix : **PASS** (45 + 1 = 46 unit tests now in
`compare::effective_tolerance::tests`).
