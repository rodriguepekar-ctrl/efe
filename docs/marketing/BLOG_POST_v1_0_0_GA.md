# Announcing EFE v1.0.0 — General Availability

Today, **2026-05-09**, the EFE team is shipping **v1.0.0 GA** —
the first stable release of the **Ephemeral Fluid Swarm** classification
platform. This is the culmination of 24 months of engineering, 22
internal milestones, 6 external betas, and feedback from over 80
early-adopter tenants across regulated industries.

> **TL;DR** : EFE v1.0.0 is a multi-tenant semantic classification gRPC
> service. Every artifact is **Sigstore-signed** and ships with **SLSA-3
> provenance**. Distribution covers 6 channels (OCI, GitHub Releases,
> Homebrew, npm, Terraform Registry, Cargo). Compliance evidence is
> auto-generated per-tenant for SOC 2, GDPR, AI Act, and ISO 27001.

## What ships today

- **`efe-server`** — the core gRPC inference service (Rust + FFI to
  llama.cpp).
- **`mcp-server`** — Model Context Protocol server with 16 read-tools +
  3 opt-in write-tools (D8 surface).
- **`portal-admin`** — Next.js 14 admin UI (RBAC, audit timeline, multi-region
  failover).
- **`efe-server-migrate`** — schema migration runner (separate image
  for clean replay semantics).
- **`efe-stack`** — Helm umbrella chart with 6 sub-charts.
- **3 Terraform modules** — AWS, GCP, Azure (rolled-up to single
  module per cloud).
- **`efe-admin`** CLI — 6 platform binaries (linux/darwin/windows ×
  amd64/arm64).
- **4 SDKs** — Python, Go, TypeScript, Java.
- **Compliance pack** — auto-generated per-tenant ZIP, cosign-signed.

## Why v1.0.0 matters

### 1. Sigstore-everywhere

Every artifact emitted by the v1.0.0 release pipeline is signed via
**cosign + Fulcio + Rekor** with a keyless OIDC identity from GitHub
Actions :

```
https://github.com/efe-ai/efe/.github/workflows/release-v1-ga.yml@refs/tags/v1.0.0
```

There are **no long-lived signing keys** for EFE artifacts. The
signing certificate is ephemeral (expires after 10 minutes) and the
inclusion proof lives in **Rekor** — an append-only public
transparency log. Anyone can audit the supply chain without contacting
EFE.

### 2. SLSA-3 provenance

Every artifact ships with **non-falsifiable provenance** generated by
`actions/attest-build-provenance@v1`. The provenance attests :
- The exact source commit SHA.
- The exact build configuration (workflow file path + input parameters).
- The build occurred on an isolated GitHub-hosted runner (not
  self-hosted).
- The provenance itself is signed by the same OIDC identity.

To verify : `slsa-verifier verify-image ghcr.io/efe-ai/efe-server:1.0.0
--source-uri github.com/efe-ai/efe --source-tag v1.0.0`.

### 3. Multi-cloud Helm + Terraform

The same `efe-stack` chart deploys unchanged on **EKS, GKE, AKS**.
Cloud-specific Terraform wrappers handle IAM, VPC, KMS, and
observability stacks while preserving operator semantics.

### 4. Compliance is a build artifact

EFE v1.0.0 is the first version where compliance evidence is **a build
artifact**. Run :

```bash
efe-admin compliance pack acme
```

…and you get a cosign-signed ZIP with :
- SOC 2 Type II readiness evidence.
- GDPR Art. 30 register entry (tenant-personalized).
- EU AI Act Art. 11 technical documentation.
- ISO 27001:2022 readiness self-assessment.
- HMAC chain integrity report.
- Live attestation status JSON.

The pack is regenerated **nightly** for every active tenant and stored
in WORM-protected per-tenant S3 buckets for **7 years**.

## What's not in v1.0.0

We deliberately deferred a few items :

- **High-risk AI Act conformity** : EFE classifies as limited-risk
  today. We have the Annex IV documentation ready in case of
  re-classification, but external conformity assessment is planned for
  2027-Q1.
- **Cargo binary crate** : the binary is shipped via OCI ; the
  `efe-server` crate on crates.io is library-only.
- **Java SDK Maven Central publication** : ships in v1.1.0 (currently
  GitHub Packages only).
- **NPM provenance for non-`@efe/sdk` packages** : we publish only
  `@efe/sdk` on npm today.

## Verifying your install

```bash
# 1. Verify the efe-server image.
cosign verify ghcr.io/efe-ai/efe-server:1.0.0 \
  --certificate-identity-regexp "^https://github\.com/efe-ai/efe/.*release-v1-ga\.yml.*" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com"

# 2. SLSA-3 provenance.
slsa-verifier verify-image ghcr.io/efe-ai/efe-server:1.0.0 \
  --source-uri github.com/efe-ai/efe --source-tag v1.0.0

# 3. End-to-end (5 min, k3d-based).
./scripts/release/verify-release.sh v1.0.0
```

Full guide : [`VERIFY_RELEASE.md`](https://github.com/efe-ai/efe/blob/v1.0.0/docs/release/VERIFY_RELEASE.md).

## Try it

```bash
# Add the Helm OCI registry.
helm install efe-stack oci://ghcr.io/efe-ai/charts/efe-stack \
  --version 1.0.0 \
  --namespace efe --create-namespace
```

Or pin in Terraform :

```hcl
module "efe_aws" {
  source  = "registry.terraform.io/efe-ai/efe-stack/aws"
  version = "1.0.0"

  tenant_id  = "acme"
  region     = "eu-west-1"
}
```
