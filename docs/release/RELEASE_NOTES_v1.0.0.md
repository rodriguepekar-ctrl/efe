# EFE v1.0.0 — General Availability

**Release date** : 2026-05-09
**Codename** : `Quartz` (first stable, archive-quality release)
**Tag** : `v1.0.0` (master) + 6 sub-tags (see [Sub-tags](#sub-tags))
**SLSA level** : 3 (non-falsifiable provenance, isolated GitHub-hosted runners)
**Signing identity** : `https://github.com/efe-ai/efe/.github/workflows/release-v1-ga.yml@refs/tags/v1.0.0`
**Rekor log index range** : *populated post-publish*

---

## TL;DR

EFE 1.0.0 is the first **GA (General Availability)** release of the
Ephemeral Fluid Swarm — a multi-tenant semantic classification gRPC
service designed for high-throughput, low-latency, hybrid-quantized
inference with full audit, compliance, and observability primitives.

This is the first release to ship with :

- **Sigstore keyless signatures** (cosign + Fulcio + Rekor) on every
  artifact (4 Docker images, 1 Helm chart, 6 CLI binaries, 1 npm package,
  3 Terraform modules).
- **SLSA-3 provenance** generated by `actions/attest-build-provenance@v1`
  on isolated GitHub-hosted runners.
- **6 distribution channels** (OCI / GHCR · GitHub Releases · Homebrew ·
  npm · Terraform Registry · Cargo) with consistent versioning.
- **VEX (OpenVEX) feed** at `docs/security/vex/feed.json` for CVE
  exploitability disclosures.
- **TUF root pinning** for offline signature verification.
- **Compliance evidence packages** (SOC 2 / GDPR Art. 30 / AI Act Art. 11
  / ISO 27001) auto-generated per-tenant and cosign-signed.

> **API stability commitment** : from v1.0.0 onward, all gRPC public
> APIs follow Semantic Versioning. Breaking changes will only ship in
> `v2.0.0` and require a deprecation window of 12 months minimum.

### Highlights

1. **Sigstore-everywhere** : every artifact emitted by this release is
   cosign-signed with keyless OIDC certs from Fulcio. No long-lived
   private keys exist for EFE artifacts.
2. **Multi-cloud Helm + Terraform** : single `efe-stack` umbrella chart
   targets EKS · GKE · AKS unchanged, with cloud-specific Terraform
   wrappers handling IAM, VPC, KMS, observability stacks.
3. **mcp-server D8 tools** : 16 read tools + 3 write tools (opt-in,
   metadata-only) covering audit, compliance, agents, deploys.
4. **Portal admin** : Next.js 14 App Router, RBAC, audit-event timeline
   with HMAC chain integrity verification, multi-region failover UI.
5. **AI Act Art. 14 / GDPR Art. 22** : human oversight hooks ship as
   first-class API surface, with attestation status reachable from
   `efe-admin compliance verify` and the portal.

## Verification

Every consumer should verify artifacts before deploying. See
[`VERIFY_RELEASE.md`](./VERIFY_RELEASE.md) for the full procedure.
Quick start :

```bash
# 1. Verify the efe-server Docker image.
cosign verify ghcr.io/efe-ai/efe-server:1.0.0 \
  --certificate-identity-regexp "^https://github\.com/efe-ai/efe/\.github/workflows/release-v1-ga\.yml@refs/tags/v[0-9]+\.[0-9]+\.[0-9]+$" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com"

# 2. Verify SLSA-3 provenance.
slsa-verifier verify-image ghcr.io/efe-ai/efe-server:1.0.0 \
  --source-uri github.com/efe-ai/efe \
  --source-tag v1.0.0

# 3. Verify Helm chart.
helm pull oci://ghcr.io/efe-ai/charts/efe-stack --version 1.0.0
cosign verify --certificate-identity-regexp "^https://github\.com/efe-ai/efe/.*" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com" \
  ghcr.io/efe-ai/charts/efe-stack:1.0.0
```

End-to-end : `./scripts/release/verify-release.sh v1.0.0`.

## Migration from v0.34 RC

For tenants on the last release candidate (v0.34) :

1. **Database migrations** : 0 new migrations vs v0.34. Migration
   sequence frozen at `0013_audit_chain_hmac.sql` (see
   `efe-server/migrations/`).
2. **gRPC API** : no breaking changes. New optional fields are
   forward-compatible per the proto3 contract.
3. **Helm values** : `values.yaml` schema is fully backward-compatible.
   New optional sections : `compliance.attestation`, `audit.chain.hmac`.
4. **CLI** : `efe-admin` v1.0.0 supports both v0.34 and v1.0.0 servers
   via auto-negotiation on the gRPC `ServerInfo` RPC.
5. **Helm rollback path** : `helm rollback efe-stack` to v0.34 remains
   supported — no irreversible schema changes since RC.

## Known issues and limitations

- **Cargo crate** : `efe-server` published to crates.io is
  **library-only** (the binary is distributed as Docker images).
  Compiling from source still works.
- **Homebrew tap on macOS Sonoma 14.x** : `cosign` from Homebrew core
  may need an explicit `brew upgrade cosign` to v2.4.0+ for SLSA-3
  attestation verification.
- **Terraform Registry publication delay** : provider/module discovery
  on `registry.terraform.io` may take up to 30 minutes after tag push.
  Direct GitHub source URLs work immediately.

## Yank / rollback policy

If a critical defect is found post-release, the response is :

1. **Sigstore signatures cannot be removed** (Rekor is append-only by
   design) — see [`SECURITY_DISCLOSURE_POLICY.md`](./SECURITY_DISCLOSURE_POLICY.md).
2. The release is **deprecated** via :
   - Docker images : `crane mutate` adds `org.efe.deprecated=true` annotation.
   - Helm chart : republished with `-yanked` tag suffix on OCI.
   - GitHub Release : converted to draft.
   - npm : `npm deprecate @efe/sdk@1.0.0 "yanked, see VEX feed"`.
   - Cargo : `cargo yank --version 1.0.0 efe-server`.
3. A **VEX statement** is appended to `docs/security/vex/feed.json`.
4. An **RSS entry** lands at `https://efe.example.com/security/feed.xml`.
5. Customers receive an email via the security mailing list within 1
   hour for P0/P1 severities.

Operator runbook : `scripts/release/release-rollback.sh v1.0.0 P1 "<reason>"`.
